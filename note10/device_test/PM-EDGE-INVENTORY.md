# PM edge software inventories

This optional, default-off diagnostic observes framework and registered-driver state at four existing points: before device suspend, after successful late suspend, after successful noirq suspend and before the existing CPU hotplug test, and after device resume. It does not add a PM transition, syscore callback, CPU hotplug operation, or hardware register access. All collectors require the ordinary eight-CPU, local-IRQ-enabled context, and run only for the existing owned PM attempt.

The DMA inventory counts all devices in the five PM lists, and separately counts DMA-capable devices. The PM flags, runtime categories, names, and mutually exclusive covered/direct-complete/syscore/uncovered categories describe only the DMA-capable set. Late and noirq flags indicate framework coverage even when a callback was absent; direct-complete and syscore exceptions are reported, not counted as proof of a device being idle. These snapshots do not establish hardware DMA shutdown.

The registered Exynos IOMMU inventory observes existing software predicates and selected exception identities with existing lock discipline; it does not touch controller registers or change runtime references. Active controllers at noirq are valid observations. A syscore device flag does not imply that the driver registered a syscore callback. The earlier and new snapshots are sequential, so runtime activity and references can legitimately change between them. Cross-lane binding compares inventory counts and name digests and the stable syscore identities; it does not require sequential runtime fields to match. Name digests are not collision-proof.

The independent syscore inventory copies the complete registered list under a nonblocking lock before suspend and after restoration. Callback presence and function symbol names are retained in registration order; null callbacks have explicit sentinel rows. Callbacks must resolve at offset zero to built-in kernel text. The two inventories must match exactly, but they are not a globally atomic snapshot with the other inventories. No callback is invoked.

Each successful record has two distinct checksummed copies tied to the build identity and PM generation. Before printing, the producer counts the complete output plus 96 bytes of conservative per-line overhead against a 65,536-byte limit. Exceeding the limit fails the diagnostic rather than accepting a partial inventory; the restored worker emits bounded failure summaries and retains the existing automatic-return path. The previous selected boot log was 818,585 bytes in one private capture; this is a variable observation, not a guarantee of future ring-buffer space. The strict decoder refuses missing, conflicting or truncated copies.

The diagnostic does not establish secure-world quiescence, syscore suspend/resume execution, GIC/MMU/cache handoff, XNU execution, or iOS boot. Per-device identities and callback inventories remain private capture data.

The prepared-file manifest binds the exact modified helper bytes and fixed upstream compositions. Kconfig is cross-checked between the build report and the prepared-source integration model. Like the existing build proof, this relies on the source commit and CI artifact provenance; matching alterations to both metadata and model output are not an independent reconstruction of the complete Kconfig composition.
