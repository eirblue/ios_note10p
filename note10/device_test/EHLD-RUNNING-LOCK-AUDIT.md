# EHLD running-state synchronization and best-effort capture

The experimental `--ehld-running-lock-audit` option is off by default. It requires both the existing EHLD lock and paired irqsave audits. Its measured marker is `CONFIG_NOTE10_EHLD_RUNNING_LOCK_AUDIT`. The v48 proof format is version 2; its validator rejects version 1. Original v47 artifacts and their version-1 source commit remain unchanged.

The source variant routes the two EHLD start/stop `ehld_running` stores through a small per-CPU control-lock helper. The helper saves IRQ state, acquires only that control lock, stores the scalar, and restores the matching state. Event creation, publication, enablement, disablement, release, logging, and MMIO remain outside the helper. The start store remains before enablement; the stop store remains after release and pointer clearing. Existing CPU-PM and raw-updater code remain unchanged.

These two stores synchronize with readers that acquire the same control lock. The earlier precondition getter still uses an unlocked `READ_ONCE` sample; the later lock getter remains a separate trylock sample. This change does not make those samples atomic, serialize the event lifecycle, or establish event readiness or lifetime.

Normal maskable IRQ and stop-IPI delivery are deferred while the scalar helper holds its irqsave lock. In v48, the all-CPU updater and dumper each try their main lock once and return if it is busy. The updater also tries each eligible CPU's control lock once and skips a busy CPU without advancing its ring index. Failed attempts restore IRQ state and do not unlock an unacquired lock. Successful paths retain their previous sampling and output behavior.

The updater is called by the periodic watchdog path as well as fatal notifiers. Contention can therefore omit a periodic sample. A later dump can contain older ring entries; it is not a fresh or complete snapshot. Only lock acquisition is bounded. Logging, MMIO and symbol lookup can still delay completion; fatal exception/NMI safety and event lifetime remain unproven.

The actual v47 CI passed with 25 bindings. Its proof reconstructs the actual v46 78-file baseline with two changed kernel files and 76 unchanged, and includes 34 host runtime cases plus nine production-transform negative controls. The v48 proof extends that same binding and includes compiled, extracted production updater/dumper functions for the changed busy/free lock paths. Local validation is limited to changed code and directly affected integration; already passed unchanged results are reused. Host fixtures remain synthetic and do not prove hardware behavior.

The existing 39 collector rows and three derived rows remain unchanged: 42 total, 41 required. The physical goal is one regression cycle with automatic TWRP return, five-partition integrity, and verified raw brightness 10 before and after the cycle. No deliberate panic, hardlockup, lock contention, direct CPU-PM invocation, event dereference, new hardware observation, XNU execution, or iOS boot is included. The v47 build passed in [CI 40903680433](https://github.com/eirblue/ios_note10p/actions/runs/40903680433). One physical cycle passed all 41 required evaluations, automatic normal TWRP return, five-partition integrity, and pre/post raw brightness 10. The battery measured immediately before installation was 96%. The v48 build passed in [CI 40916389727](https://github.com/eirblue/ios_note10p/actions/runs/40916389727). One ordinary physical cycle passed all 41 required evaluations, automatic normal TWRP return, five-partition integrity, and pre/post raw brightness 10. The battery measured immediately before installation was 90%. Contended observer branches were checked with compiled host models; no panic, hardlockup or contention was induced on-device.
