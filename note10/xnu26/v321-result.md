# v321 XNU binds the interrupt controller and stops at the post-bind checkpoint

**Qualification PASS.** Source `590e136639eeccdf118a12093ad8a5b1666ef2f5` built successfully on the first attempt in CI run `44966265154`. The new v321 fixture (4 groups, 14 variants, 14 assertions) passed; earlier checks were not replayed. The v316 stub and Linux sources were reused byte-identical, and the record tag becomes `N321PS20`.

In v320 core 0 stopped at the marked platform-contract check in XNU's interrupt-controller initialization, because the device tree had no `/chosen/note10-platform` node. Supplying that node lets XNU set up and access the interrupt controller (GIC) itself. This build is the first in which XNU performs device MMIO. It runs under the user's explicit approval of 2026-11-22 for XNU-owned GIC access, with a GIC safety analysis reviewed before the cycle.

v321 bundles:

- **Device-tree node.** `/chosen/note10-platform` is added as the second child of `/chosen`. It carries a compatible string, version 1, a `gic-handoff` flag, the GIC distributor and CPU-interface regions (`N321_GICD_BASE` `0x10101000` and `N321_GICC_BASE` `0x10102000`, 4 KiB each, public Exynos 9825 values), timer interrupt 30, and a timebase frequency equal to the CPU node's. The device tree grows by 352 bytes and still fits the 4096-byte storage.
- **Validator.** A v321 copy of the runtime ADT validator accepts the `gic-handoff` property key, which the earlier validator refused as a pre-approval lock. The check on node names stays. The original validator is untouched for earlier builds.
- **Private markers.** A private image patch adds a checkpoint self-spin directly after a successful GIC bind, so XNU stops at a deterministic point. It also gives every failure branch of the bind, and every property check of the platform node, its own self-spin. The earlier markers remain.
- **Unchanged.** boot_args, the seed, the handoff layout, the stub, the Linux code, the bootstrap map limit and the reservation are identical to v320.
- **Offline prediction.** Before use, the emulator from v320 was extended with a GIC register model. In that emulation XNU found the platform node, mapped the GIC regions and read five identification and control registers. It accepted the enabled state Linux leaves behind, wrote one banked enable for timer interrupt 30 on CPU 0, and stopped at the checkpoint. Interrupts stayed masked throughout. The modeled register values are synthetic defaults, not device readings. A counter-run with the CPU interface modeled in a different EOI mode made no write and stopped at the matching bind-failure marker.

On the device, the stub ran every check, committed the `N321PS2T` record and branched to XNU. The record, bound to the current build, boot and cycle, matched the precomputed values exactly. It covers the device tree including the new node.

After the reset, the log read back from the previous boot held all three v315 breadcrumbs, in order, directly after the record. The builder code was 0. The boot loader's next log block reported a cluster-0 watchdog reset, with core 0 stopped at the post-bind checkpoint spin, as predicted. Normal TWRP returned in a distinct boot epoch about 57 seconds after the actor started, within the 240-second bound. All five partition integrity checks passed, and the recovery setting and panel brightness both read back 10. The cycle used one BOOT write, one host reboot, one actor invocation and one XNU branch; RECOVERY writes and rollback BOOT writes were zero.

This qualifies the build as far as the checkpoint shows. The device shows only that core 0 was in the post-bind checkpoint spin at the reset. It was not in any bind-failure or property-check marker, the v320 platform marker, any earlier marker, `_panic_spin_forever` or the debugger trap path. That is consistent with the offline prediction. Reaching the checkpoint means XNU's bind code took its success path. The specific GIC access pattern (five reads, one banked enable write, interrupts masked) comes from the offline emulation, not from the device, and no GIC register values were recorded on the device.

Next is removing the checkpoint so XNU continues into timebase and kernel bootstrap. That needs better emulator fidelity first, and a renewed GIC safety analysis before interrupts are unmasked. Interrupt handling, later kernel bootstrap and independent native return remain unproven.
